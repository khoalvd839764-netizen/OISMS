## B02-F04 — P2 — Ba đường đồng bộ vẫn chưa đạt AC

AC T03-AC-03/05/06/07; R1 đã yêu cầu refetch theo contract, response đến muộn không thắng và reconnect khôi phục dữ liệu. Source trong `src/frontend/pos-app` trừ controller backend được ghi rõ.

1. **Refetch từ StockLevelChanged tìm UUID bằng endpoint chỉ tìm text.** `src/services/realtimeService.ts:329–332` truyền chỉ `{ skuId }`. `src/services/api.ts:1075–1083` dùng UUID làm query của `/api/pos/search`. `src/backend/src/OISM.WebApi/Controllers/PosCatalogController.cs:68–78` chỉ filter SKU/product name/barcode, không filter variant ID. Với SKU thông thường mã `SKU-A`, event chứa ID `33333333-...` thì GET trả [] dù hàng tồn tại. Probe fixture đúng predicate backend: server8, cache10 → event → GET query UUID → cache vẫn10/stale=true. Không khẳng định đã phát event trên backend thật trong lượt này.
2. **Sequence guard tách theo alias, không theo identity cùng mặt hàng.** `src/services/api.ts:1061–1066`, `:1087–1089`: key là branch+lookupKey. Request search code SKU-A cũ đang chờ; request barcode của cùng variant mới trả8; response search cũ trả10 vẫn được ghi vào cùng cache. Probe actual service xác nhận **8→10** vì key SKU code khác key UUID. Các lookup search/barcode hiện có đều hợp lệ, đây là regression của cơ chế guard v1.1 chưa bao phủ cùng identity.
3. **Reconnect chỉ rejoin, không refetch stock store.** `src/services/realtimeService.ts:276–294` gọi reconnectedListeners nhưng không có caller đăng ký `subscribeReconnected` trong source POS. Khi stockService chuyển thành proxy, subscriber reconnect trước đây đã bị bỏ. Probe actual handler: server đổi10→8 trong lúc offline, gọi onreconnected → join lại đúng branch nhưng **0 GET**, cache vẫn10. Cần phục hồi số chuẩn sau khi lỡ event; không chờ giao dịch tiếp theo để may mắn nhận event mới.

Điều kiện đóng: dùng nguồn API hiện có đúng contract để refresh SKU ID (resolve identity/mapping/context phù hợp, không tự sửa backend ngoài brief); canonical identity/context cho freshness giữa alias và đường GET; reconnect refresh những SKU liên quan view/cart của owner/branch hiện hành. Guard response/context cũ cả khi đổi phiên, giữ stale/retry trung thực nếu không thể refresh. Test production handler với HTTP fixture bám predicate thật, alias response đảo thứ tự và reconnect mất event; transport thật ở F06. Không chỉ mock mọi query đều trả SKU đang cần.

## B02-F05 — P2 — Ca branch đã sửa; clear query vẫn nhận kết quả cũ

AC T05-AC-06 và điều kiện đóng R1. `src/components/ProductSearch.tsx:98–109`, `:129–155`, `:298–302`.

Khi query đổi thành rỗng, effect xóa results/dropdown rồi return, không tăng requestId/abort request đang chờ. Effect cleanup của search chỉ clear timeout (`:170`), không vô hiệu callback đã chạy. Guard requestId chỉ tăng lúc debounce mới chạy, nên request cũ vẫn hợp lệ khi query bị xóa hoặc trong cửa sổ trước debounce query mới.

Repro actual ProductSearch/lifecycle harness: nhập SKU-A → timer200ms phát GET đang giữ → xóa input → trả GET cũ → input rỗng nhưng dropdown cũ mở lại với 1 hàng có thể chọn. Ca barcode đổi branch đã PASS và được giữ riêng trong results; không mở lại lỗi branch đã sửa.

Đóng khi mọi query edit/clear vô hiệu ngay callback cũ, không đợi debounce tiếp; success/error/finally/latency của request hết hiệu lực không sửa UI hiện hành. Có regression promise điều khiển query A→clear và A→B trước debounce, ngoài ca branch đã pass; source-string assertions không chứng minh race đã đạt.
