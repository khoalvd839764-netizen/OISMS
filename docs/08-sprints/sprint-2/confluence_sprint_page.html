II. Cơ cấu Phân vai & 12 Quy tắc Làm việc Nhóm Đồng thời

#

Quy tắc làm đồng thời

Quy định bắt buộc

1

Thống nhất UI từ sớm

Cả nhóm thảo luận và chốt UI từ Figma đã có. TV3 (Admin) và TV4 (POS) tự code và tự nối API trong ứng dụng của mình; Khoa không phải nối toàn bộ giao diện.

2

Ký kết Hợp đồng giao tiếp (Contract First)

Ngay D1 mỗi Sprint, chốt rõ session, DTO, endpoint, mã lỗi và interface giữa Order / Reserve / Ledger. Quy ước chung: toàn bộ dùng camelCase, format chuẩn cho ID, thời gian và error.

3

Bàn giao theo lát cắt nhỏ

Khoa bàn giao Entity và persistence theo từng nhóm nhỏ: account/tenant → catalog/warehouse → ledger/receipt → order/reservation. TV2 không phải đợi toàn bộ schema xong mới viết module.

4

Tự kiểm thử trước bàn giao

Backend tự viết unit/integration test trước khi bàn giao endpoint. TV5 chuẩn bị testcase ngay từ contract, test trên Swagger khi có API và trên UI khi FE nối xong.

5

Ghép nối cuốn chiếu

Một feature chia làm nhiều lát: đọc → tạo/sửa → action nghiệp vụ. FE nối ngay endpoint nào ready, không dời toàn bộ việc ghép API sang Sprint sau.

6

Lập trình theo interface khi thiếu phụ thuộc

Nếu phụ thuộc chưa có, viết theo interface đã chốt kèm test double; FE làm form/loading/error/print. Tuyệt đối không hardcode fake success vào ứng dụng thật.

7

Dùng dữ liệu thật 100%

Bản chính thức dùng API thật; API lỗi/chưa có hiện đúng trạng thái không fallback số giả. Trình giả lập Webhook gửi payload thật vào backend và nhận kết quả thật.

8

Trách nhiệm phân tầng mã nguồn

Khoa giữ Entity, DbContext và migration; TV2 đề xuất thay đổi cần thiết qua PR review, tự viết DTO, validator, service cho module mình.

9

Yêu cầu gộp mã nhỏ gọn (Small PRs)

PR nhỏ, bàn giao hàng ngày hoặc khi lát chức năng xong. Khoa dành khung review có giới hạn; các API blocking được ưu tiên số 1 thay vì làm tính năng phụ.

10

Định nghĩa Hoàn thành (Definition of Done)

Done = code đúng + endpoint/backend test đạt + FE nối + TV5 kiểm thử đạt + dữ liệu đọc lại đúng + testcase/docs được cập nhật đầy đủ.

11

Bảo đảm kiểm thử tự động 80% lõi

Automated tests/coverage ≥80% phần lõi (Sổ kho, Giữ chỗ, WAC) thuộc trách nhiệm backend, chủ yếu Khoa phụ trách. Swagger không thay thế cho automated test.

12

Họp ngắn blocker hàng ngày

Mỗi ngày trao đổi ngắn blocker và API mới; cả nhóm review UI theo feature thay vì dừng toàn bộ code để cùng sửa một màn hình.

III. Phân công Chi tiết theo từng Sprint (Kế hoạch Mới Hoàn thiện)

1. Sprint 1 (09/10/2026 – 12/10/2026): Khởi tạo & Đặc tả yêu cầu

Mục tiêu: Thu thập và tổng hợp yêu cầu người dùng; hoàn thành tài liệu đặc tả yêu cầu phần mềm và kế hoạch quản lý dự án; dựng sẵn khung sườn mã nguồn và môi trường ảo hóa khởi chạy; đào tạo nội bộ và báo cáo giai đoạn 1.

2. Sprint 2 (13/10/2026 – 17/10/2026 | D1 – D6): Nền tảng & Luồng Dữ liệu Đầu tiên

Mục tiêu: Hoàn thành database nền tảng và có luồng thật: đăng nhập → tạo SKU → lập/xác nhận nhập → xem tồn/ledger/giá vốn. Đơn/POS có contract và bắt đầu hiện thực sớm, không để mọi phần khó tới Sprint 3.

Thành viên

Nhiệm vụ cụ thể

Kết quả bàn giao


(Backend chính)

• Schema, Entity, mapping, DbContext, migration và seed dữ liệu.
• Chốt cách phản ánh onHand theo ledger, tenant scope và query filter cô lập dữ liệu.
• Xây dựng Sổ kho bất biến (Append-Only Ledger), xác nhận nhập kho nguyên tử (Atomic), tính giá vốn WAC tự động.
• Lõi Order / Reservation và thử nghiệm khóa database sớm.
• Mẫu xử lý HTTP, xác thực, quản lý giao dịch và Docker/CI nền tảng.

Database tái tạo được hoàn toàn; API nhập/tồn/sổ chạy thật; công thức giá vốn có test; interface đơn/giữ chỗ sẵn sàng; kịch bản test khóa đạt.


(Backend phụ)

• Module băm mật khẩu, cấp và refresh JWT token (login/logout/refresh/me) theo template của Khoa.
• Chức năng đăng ký cửa hàng (Tenant registration) dưới sự rà soát của Khoa.
• Xây dựng API CRUD và tra cứu: Cây danh mục, Thương hiệu, Sản phẩm, Biến thể SKU, Bảng giá, Mã vạch.
• Tra cứu nhà cung cấp, chi nhánh/kho cần dùng; viết FluentValidation; phối hợp Khoa bổ sung quyền/tenant guard.

API auth/catalog và các DTO theo lát nhỏ; bài test đơn vị đạt; ràng buộc duy nhất và cô lập dữ liệu được bảo đảm.

• Hoàn thiện Web Admin trên React 19, gỡ bỏ toàn bộ dữ liệu cứng/mặc định Owner.
• Quản lý trạng thái đăng nhập, điều hướng phân quyền, hiển thị rõ loading, lỗi mạng, lỗi 403.
• Xây dựng các form Danh mục, Thương hiệu, Sản phẩm, Phiếu nhập kho nhiều dòng, Sổ kho và tồn kho.
• Nối trực tiếp các API ngay khi được bàn giao.

Admin thao tác và đọc lại database được; loading/error/403 rõ ràng trên cổng 5173.

• Hoàn thiện Web POS PWA trên React 19, gỡ bỏ giỏ hàng mẫu.
• Xây dựng chức năng tìm kiếm và quét SKU từ API thật, giỏ hàng nhiều dòng, tiền khách nhập, mã QR và bản in hóa đơn.
• Chuẩn bị checkout theo contract; thiết lập PWA nền tảng.

POS tra cứu SKU thật; checkout chưa sẵn sàng không báo thành công; bản in hóa đơn chuẩn bị sẵn dùng dữ liệu API.

• Viết testcase cho FR-AUTH, FR-PROD, FR-INV, FR-COST gồm dữ liệu hợp lệ/không hợp lệ, cô lập tenant và vai trò.
• Kiểm thử từng API trên Swagger; kiểm thử giao diện luồng nhập/kho/giá vốn.
• Ghi nhật ký lỗi (bug log), xác nhận sửa lỗi và cập nhật ma trận RTM.

Testcases kèm kết quả kiểm thử Swagger/UI; danh sách lỗi/retest; bằng chứng luồng dữ liệu đã chạy thật.
